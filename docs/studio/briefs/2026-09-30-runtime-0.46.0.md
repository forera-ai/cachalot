# Codex brief — runtime 0.46.0 (2026-09-30)

Tracks Cachalot runtime **0.46.0** (HANDOFF section 18.29). One new environment knob, one new log line, no endpoint,
stats field or default in the launch scripts changed.

- **New knob (GLM and MiniMax server):** `CACHALOT_LOOP_GUARD_INCREMENTING` (default 64; 0 turns it off). A reply
  that ends with that many list items differing only in one integer counting up by one, none of them in the prompt,
  stops with `finish_reason: stop`. It belongs next to `CACHALOT_LOOP_GUARD_REPEATS` in the launch panel's advanced
  section, default shown.
- **New log line:** `[loop guard] reply stopped after N tokens: 64 list items counting up by one, none of them in the
  prompt`. The existing `[loop guard] reply stopped after N tokens: a K-token block repeated 6 times` is unchanged. A
  Cockpit that flags loop-guard stops should match the common prefix `[loop guard] reply stopped after`.
- **Temperature (no change yet, a likely next one):** the session measured a lower sampling temperature for agent
  requests (they send none; MiniMax's server default is 1.0). If Hamed adopts it through the server, it arrives as
  `./serve-minimax.sh --default-temperature 0.7`, visible in the startup line `a request without them samples at
  temperature 0.7, top_p 0.95`. A launch-panel field for the default temperature (MiniMax 1.0, GLM from its
  checkpoint, DeepSeek 0.6) would let him switch it without a terminal.

# Codex brief — runtime 0.40.0 (2026-09-29)

Tracks Cachalot runtime **0.40.0** (HANDOFF section 18.21 items 7-9). Since the 0.39.0 brief: 0.39.2 fixed lost
MiniMax tool calls (no contract change), 0.40.0 adds a loop guard.

## 1. Contract-file edits

### `runtime-contract/knobs.yaml`

```yaml
- key: CACHALOT_LOOP_GUARD_REPEATS
  kind: env
  families: [glm-5.3-flash, minimax-m3]
  type: int
  default: {glm-5.3-flash: 6, minimax-m3: 6}
  range: [0, 50]
  group: decode
  effect: changes-output
  restart_required: true
  stability: shipped
  since: 0.40.0
  summary: >-
    A reply whose last N blocks of 10-200 tokens are the same block, back to back, stops there (finish_reason
    stop). 0 turns the guard off. Only degenerate repetition is cut.
  doc: HANDOFF 18.21 item 9
```

### `runtime-contract/log-lines.yaml`

```yaml
- id: loop_guard
  since: 0.40.0
  families: [glm-5.3-flash, minimax-m3]
  regex: '^\[loop guard\] reply stopped after (?P<tokens>\d+) tokens: a (?P<block>\d+)-token block repeated (?P<repeats>\d+) times$'
  meaning: The reply looped and was stopped; it precedes that request's [request] line.
```

### `runtime-contract/compat.yaml`

- `loop_guard: ">=0.40.0"`.

## 2. UI changes

- **Logs / Cockpit:** show a `[loop guard]` event as a warning chip on the request it belongs to ("reply looped,
  stopped at N tokens"); count them per session in the Cockpit's request panel.
- **Profiles → Decode (GLM, MiniMax):** "Stop looping replies" switch, on by default, writing
  `CACHALOT_LOOP_GUARD_REPEATS=0` only when turned off; advanced: the repeat count.
- No `/v1/stats` field, endpoint or CLI flag changed.

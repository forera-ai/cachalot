# Lab brief: runtime 0.64.0, the per-token trace for DeepSeek decode (HANDOFF section 18.134)

Contract-file diffs first. Everything below exists only when the DeepSeek server starts with **`CACHALOT_TOKEN_TRACE=1`** (new knob, default off). With the knob off nothing changes: no new field, no new log text, no hook cost beyond one attribute test. GLM and MiniMax servers print a notice and ignore the knob.

- **New knobs:** `CACHALOT_TOKEN_TRACE=1` turns the trace on (`0`, `off`, `false` or unset leave it off); `CACHALOT_TOKEN_TRACE_EVERY=N` records one decode token in N (default **4**; `1` records every token). At startup the server prints `token trace on (CACHALOT_TOKEN_TRACE): one decode token in N is recorded ...`.
- **`/v1/stats`: new object `token_trace`** (absent with the knob off):
  ```json
  {"every": 4, "sampled_tokens": 86, "requests": 3, "dropped_events": 0, "exposed_read_share": 0.6,
   "mean_per_sampled_token": {"wall_ms": 153.2, "sync_ms": 62.4, "blocked_ms": 62.8, "read_busy_ms": 104.4,
                              "hidden_read_ms": 43.1, "reads": 66.3, "bytes": 659000000, "events": 294}}
  ```
  The values are running means over every sampled decode token since the server started (the trace is drained into the sums at the end of each request). `exposed_read_share` is `blocked_ms / read_busy_ms` summed over the sampled tokens, or `null` before any read is seen. No per-request field and no `[request]` log text were added.

What the numbers are and are not (show this in the UI):

- `sync_ms` is the time inside the router `mx.eval` of each MoE layer, summed over a token. It includes the GPU work queued before the sync, so it is **not** pure compute or pure waiting.
- `blocked_ms` is the time the main thread is inside the call that returns the layer's experts: the **exposed** I/O. `read_busy_ms` is the union of the drive-read intervals of all worker threads in the token's window; `hidden_read_ms` is the part of it outside the blocked intervals. A read that straddles a token boundary is dropped from both, so shares are approximate by a few percent.
- The trace has no GPU timeline. "Exposed" is the main thread's wait, a lower bound on what a faster drive would buy, not a proven critical path.
- Sampling is by position (every Nth decode token), so the means are over a sample. Measured cost of **continuous** recording is +0.55 ms a decode token (95 % +0.05 to +1.11, HANDOFF 18.133), so the 1-in-4 default costs about 0.14 ms averaged; label any continuous setting with that cost.
- Numbers from one run at a 34-38 GiB budget: about 57-60 % of drive-read time is exposed, a token of 127-155 ms has 60 ms of router sync and 41-63 ms blocked. These are tagged **measured** for that run only; do not present them as a property of the model.

Rules for Lab: a missing field shows as unavailable, never zero; a derived share is never styled like a measurement; do not infer a critical path from these means; the runtime owns the instrumentation, Lab owns interpretation.

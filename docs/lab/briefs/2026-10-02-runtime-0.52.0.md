# Codex brief — runtime 0.52.0 (2026-10-02)

Tracks Cachalot runtime **0.52.0** (HANDOFF section 18.48). GLM gains video input; nothing else changed.

- **Endpoint behaviour:** `./serve-glm.sh` (model id `glm-5.3-flash`) accepts OpenAI-style `video_url` content parts (also `video` / `input_video`; a `data:` URI, an http(s) URL or a
  local path) in `/v1/chat/completions`. The server samples 2 frames per second with ffmpeg (up to `CACHALOT_GLM_VIDEO_MAX_FRAMES`, default 128) and spends at most
  `CACHALOT_GLM_VIDEO_MAX_TOKENS` (default 4000) image tokens on the whole clip, so a long clip is shrunk in resolution, not cut. A 6 s clip is about 1,200 tokens and prefills in
  ~25 s (about 50 tok/s); a resent clip reuses its prefix.
- **Stats:** `images_served` in `/v1/stats` and `images=N` in the `[request]` line now count video steps (two frames each) as well as images; a 6 s clip adds 8.
- **Studio:** enable video attachment for GLM; limit the file size you read into a base64 `data:` URI (a few tens of MB). MiniMax has no vision; DeepSeek does not read video.

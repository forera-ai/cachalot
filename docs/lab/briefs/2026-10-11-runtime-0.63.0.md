# Lab brief: runtime 0.63.0, energy per request and per token (HANDOFF section 18.129)

Contract-file diffs first. Everything below exists only when the server starts with **`CACHALOT_ENERGY=1`** (new knob, default off, all three model families). With the knob off nothing changes: no new field, no new log text, no sampler.

- **New knob:** `CACHALOT_ENERGY=1` turns the meter on; `CACHALOT_ENERGY_INTERVAL` (seconds, default 1.0) is its sampling interval. At startup the server prints `energy meter on (CACHALOT_ENERGY=1): ...`.
- **`/v1/stats`: new object `energy`** (absent with the knob off):
  ```json
  {"enabled": true, "available": true, "sample_interval_seconds": 1.0, "samples": 7, "last_sample_age_seconds": 0.96, "since": 1791713761.68,
   "system":     {"available": true,  "watts": 36.7, "joules": 314.4, "source": "SMC PSTR (whole-system power, integrated at the sampling interval)", "tag": "measured", "reason": null},
   "components": {"available": false, "joules": null, "source": "IOReport Energy Model", "tag": "measured",
                  "reason": "CPU, ANE, DRAM, DCS and AMCC counters advance only while a root powermetrics samples beside the server"}}
  ```
  `system.joules` is cumulative since the meter started (`since`, epoch seconds). When `components.available` is true, `components.joules` is `{cpu, gpu, ane, dram, dcs, amcc}` cumulative joules since start. `available: false` always carries a `reason`; Lab must show it as unavailable, never as zero.
- **`usage.cachalot.energy`** on every chat/completion response (and the final streaming usage chunk when `include_usage` is set):
  ```json
  {"available": true, "tag": "measured", "source": "SMC PSTR ...", "sample_interval_seconds": 1.0,
   "request": {"seconds": 2.854, "system_joules": 135.19, "mean_system_watts": 47.37, "components_joules": null},
   "decode":  {"seconds": 0.888, "system_joules": 50.42, "mean_system_watts": 56.77, "system_joules_per_token": 7.2026, "components_joules": null},
   "components_available": false, "components_source": "IOReport Energy Model"}
  ```
  `request` is the whole request window (prefill and decode, queue time excluded); `decode` is the last `decode_seconds` of it and carries joules per output token. When the window has no usable samples: `{"available": false, "reason": "...", "tag": "measured"}`. `components_joules` is `null` unless the component counters were moving.
- **`[request]` log line:** a new ` J/tok=7.20 W=56.8` (decode-window system joules per output token and mean watts), or ` J/tok=n/a`, placed before `finish=`; absent with the knob off.

What the numbers are and are not (show this in the UI):

- **System** energy is the integral of the SMC's whole-system power (`PSTR`) at the sampling interval, tag **measured**. It needs no root. It includes everything on the machine (other applications, the display), so a figure for one request is only meaningful on a quiet machine; the first request after start-up and requests shorter than a few seconds carry up to one interval of sampling error at each end (the example above is 7 tokens).
- **Components** are the SoC's own energy estimates (IOReport). They are available only while the user runs a root `powermetrics` beside the server (the counters stay frozen otherwise), they do not add up to the system figure (the component fit is about 15 % short for quantized kernels, HANDOFF 18.128; the SSD has no sensor), and must never be styled as a breakdown of the system total. `coverage = components / system` may be shown as such.
- There is no SSD or DRAM-transport figure at the runtime. Those are derived offline (HANDOFF 18.119, 18.121, 18.125: DRAM about 50 pJ per byte, the internal SSD about 1.1 W per GB/s, the X10Pro about 2.7 W at 1 GB/s) and are Lab's to label **derived** if it applies them to a request's bytes.
- Planned views from `docs/POWER-ACCOUNTING-PLAN.md` section 5 remain Lab's to build: joules per token against token time, a live power strip next to tokens per second, a two-run comparison with the baseline subtracted, a coverage indicator. This brief only fixes the contract.

Rules for Lab: a missing source shows as unavailable, never zero; an estimate is never styled like a measurement; do not collect power with sudo; the runtime owns the instrumentation, Lab owns interpretation.

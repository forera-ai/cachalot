# Lab brief: runtime 0.78.0, a default-off prefill rare-expert skip (HANDOFF section 18.259)

Contract-file diffs first. **One new knob, off by default:** `CACHALOT_PREFILL_RARE_SKIP=k` (unset, empty, `0`, `off` or `exact` = off) with
`CACHALOT_PREFILL_RARE_MIN_ROWS` (default 1024). With it on, a DeepSeek prefill call of at least that many rows does not read the routed experts
that at most `k` of its rows route to, and rescales those rows' other router weights. It changes outputs and is under test
(`docs/prefill-rare-skip/RECORD.md`); no launcher sets it.

- **Startup line (new, only when on):** `prefill rare-expert skip: in a prefill call of at least <min> rows an expert routed by at most <k> rows is not read ...`
- **`[request]` line (new field, only after the rule has applied once):** ` rare_skip=<experts skipped>/<mass dropped>%`, cumulative since the
  server started, placed after the energy fields and before `finish=`. Absent when the knob is off, so existing parsers see no change on the shipped defaults.
- **Snapshot key:** with the knob on, the DeepSeek numerics tag gains `-rare<k>m<min>` (for example `...-di1.1-keep140-rare2m1024`), so its
  snapshots are kept apart from the shipped ones. Unchanged when off.
- No `/v1/stats` field, endpoint, default or launcher changed. `cache_sim.py` defaults moved to the 1017 checkpoint in 0.77.2 (instrument only).

UI notes for Lab: an A/B view of prefill seconds by request size would show this lever best (it acts on single-call prompts of 1,024 to 4,096
tokens and on the first call of longer ones); the `rare_skip=` counter is cumulative, so a per-request value is the difference from the previous line.

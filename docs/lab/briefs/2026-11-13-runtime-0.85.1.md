# Lab brief: runtime 0.85.1, GLM per-layer prefill log (HANDOFF section 18.277)

Contract-file diffs first. **One instrument knob added, default off:** `CACHALOT_GLM_PREFILL_LOG=1`. When set, a GLM server prints one stderr line per prefill layer call:

```
[prefill-layer] layer=12 rows=2048 routed=288 ahead=whole:288 wait_ms=301.4
```

- `rows`: tokens in the chunk; `routed`: distinct experts the chunk routes to in this layer; `ahead`: what the layer read ahead for the next one (`none`, `whole` = every expert of the next layer, `pred` = the predicted union of `CACHALOT_GLM_PREFILL_PREDICT_TOPK`, `given` = a caller's list) and how many entries; `wait_ms`: how long the store took to hand back this layer's experts. A cold 15.6k-token block prints about 380 lines.
- **What Lab may show:** if Lab tails server stderr, it can parse these lines into a per-chunk read-wait view (sum `wait_ms` per run of 42 lines at the same `rows`). In 18.277 that view showed a cold block's time varying by 5-9 s on single chunks, which is what Lab's comparison views would need to separate the machine from a knob.
- `CACHALOT_GLM_PREFILL_PREDICT_TOPK` (0.85.0) is closed as a lever and stays off.
- No default, `[request]` field, `/v1/stats` field, endpoint or snapshot format changed; no numerics bump.

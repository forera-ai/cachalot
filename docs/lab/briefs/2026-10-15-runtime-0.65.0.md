# Lab brief: runtime 0.65.0, `CACHALOT_FP8_GEMV_DECODE` (HANDOFF section 18.153)

Contract-file diffs first. One new knob, default off; with it unset or `0` nothing changes: no new field, log text, endpoint or stat.

- **New knob:** `CACHALOT_FP8_GEMV_DECODE=1` (also any value other than `0`) makes the DeepSeek FP8 GEMV decode its E4M3 weight bytes arithmetically instead of through a lookup table. Outputs are bit-identical to the default (tested over all 256 weight codes and inside `mx.compile`); no numerics tag change, so snapshots stay valid. Read once at import (a restart is needed to change it).
- No `/v1/stats` field, log line, startup phase, endpoint, `serve*.sh`/`chat*.sh` default or model family changed.

UI notes for Lab: list the knob with its default (off) among the DeepSeek runtime switches if Lab shows environment knobs. Measured (microbenchmark, random buffers, two processes): `wo_b` 0.1107 to 0.0775 ms and `wq_b` 0.0937 to 0.0801 ms a layer, at most 1.6-1.9 ms of the 80 ms floor; there is no server-level measurement, so do not show a token-speed gain for it.

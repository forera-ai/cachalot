# Codex brief — runtime 0.39.0 (2026-09-28)

Tracks Cachalot runtime **0.39.0** (HANDOFF section 18.21). The contract in `CODEX-STUDIO-PROMPT.md` was written
against 0.38.1; this brief lists what changed since. Apply the contract-file edits first, then the UI changes.

## 1. Contract-file edits

### `runtime-contract/knobs.yaml` — three new knobs (MiniMax family only)

```yaml
- key: CACHALOT_MINIMAX_MISS_DROP
  kind: env
  families: [minimax-m3]
  type: float
  default: {minimax-m3: 0}
  range: [0, 0.25]
  unit: share of a layer's routing weight
  group: decode
  effect: changes-output
  restart_required: true
  admin_required: false
  stability: experimental
  since: 0.39.0
  summary: >-
    A missing decode expert whose share of its layer's routing weight is below this is not read from disk
    (0 = exact path). Recommended value 0.20 together with CACHALOT_MINIMAX_MISS_SUB=4.
  doc: HANDOFF 18.21

- key: CACHALOT_MINIMAX_MISS_SUB
  kind: env
  families: [minimax-m3]
  type: int
  default: {minimax-m3: 0}
  range: [0, 8]
  group: decode
  effect: changes-output
  restart_required: true
  admin_required: false
  stability: experimental
  since: 0.39.0
  summary: >-
    With MISS_DROP > 0: replace a skipped expert with the best-scored resident expert among the next N ranks
    (0 = leave it out). Always use 4 with MISS_DROP; leaving experts out without a replacement was measured unsafe.
  doc: HANDOFF 18.21

- key: CACHALOT_MINIMAX_MISS_DROP_ARMED
  kind: env
  families: [minimax-m3]
  type: bool
  default: {minimax-m3: false}
  group: debug
  effect: bit-identical
  restart_required: true
  stability: debug
  since: 0.39.0
  summary: Copies routing weights to the host even at MISS_DROP 0 (benchmark instrumentation only).
  doc: HANDOFF 18.21
```

### `runtime-contract/compat.yaml`

- `minimax_miss_substitution: ">=0.39.0"`.

### No changes

- `/v1/stats` fields, `[request]` log-line fields, startup phases, endpoints, CLI flags and the serve scripts'
  defaults are unchanged (the serve/chat scripts only gained a comment).

## 2. Behaviour the Studio must know

- **Not bit-identical.** This is the first shipped runtime speed option that changes outputs. Measured quality:
  inside the band of a rounding-order change on three texts, 24/24 checkable tasks either way; long context,
  thinking mode and tool calls not yet gated. Speed: MiniMax decode −9 to −13.5 % per token through the server,
  misses per token −40 %.
- **Disk snapshots are keyed by the setting** (`NUMERICS_TAG` gains `-missdrop0.2-sub4`). Toggling it means the
  prefix snapshots written under the other setting are not reused: the first request after a toggle re-prefills
  its system block (minutes for a Hermes-sized ~20k block). Say so in the confirmation.
- The two knobs belong together: expose them as one Profile control, not two free fields.

## 3. UI changes

- **Profiles → Decode (MiniMax only):** a switch "Skip light expert misses (approximate)" that writes
  `CACHALOT_MINIMAX_MISS_DROP=0.20` and `CACHALOT_MINIMAX_MISS_SUB=4`, off by default. `changes-output` badge and
  `experimental` badge; enabling it asks for confirmation with the two facts above (outputs change; snapshots
  under the other setting are not reused). Advanced view may expose the threshold (0.10-0.20 slider, values above
  0.20 disabled with the note "0.25 measured unsafe").
- **Cockpit:** when the running profile has it on, show a small "approximate decode" marker next to the model
  name, so a user comparing answers knows which mode produced them.
- **Chat / API views:** nothing new.

## 4. Runtime requests this brief answers or opens

- Opens: the runtime should report the active numerics mode in `/v1/stats` (e.g. `numerics_tag`) so the Studio
  does not have to infer it from the environment it launched with. Not implemented in 0.39.0; Studio fallback:
  read it from the profile it launched.

# Lab brief: runtime 0.77.1, an oversized `max_tokens` is shortened, not refused (HANDOFF section 18.257)

Contract-file diffs first. **One API behaviour changed** (`/v1/chat/completions` on the DeepSeek, GLM and MiniMax servers; `/v1/completions` is unchanged and still refuses either way): a
request whose `max_tokens` (or `max_completion_tokens`) exceeds `max_seq_len` minus the prompt now runs with the cap shortened to the room left,
instead of failing with `Prompt + requested generation exceeds runtime max_seq_len`. A prompt that leaves no room still fails with that message.
No knob, default, startup line, `/v1/stats` field, `[request]` field or snapshot key changed; outputs are unchanged up to the cap.

UI notes for Lab: if Lab counts failed requests, the `max_seq_len` failure now means the prompt itself is too long; a shortened request shows as
`finish=length` when it reaches the cap.

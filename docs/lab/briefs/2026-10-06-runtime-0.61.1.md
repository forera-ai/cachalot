# Lab brief: runtime 0.61.1 (HANDOFF section 18.78)

Contract-file diffs first:

- `/v1/stats` for the GLM-5.3-Flash and MiniMax-M3 servers (`./serve-glm.sh`, `./serve-minimax.sh`; both use `cachalot.glm.engine.GlmEngine`) gains eleven numeric fields, all cumulative since the server started:
  - `expert_hits`, `expert_misses` (int): expert-store lookups that hit or missed (prefill and decode).
  - `predicted_loads`, `predicted_used` (int): speculative next-layer expert loads started, and those a later layer then used. Precision is `predicted_used / predicted_loads`.
  - `ssd_bytes_read` (int, bytes), `expert_reads` (int), `expert_fast_reads` (int, reads fast enough to have come from the page cache), `expert_read_seconds` (float, summed read wall time; reads overlap, so this exceeds elapsed time).
  - `expert_read_busy_seconds` (float): wall time with at least one read in flight; `ssd_bytes_read / expert_read_busy_seconds` is the drive's rate while reading.
  - `decode_wait_seconds` (float), `decode_waited_misses` (int): time decode waited for its misses' reads, and how many misses it waited for.
  The first eight have the same names and meaning as DeepSeek's `/v1/stats` fields; the last three exist only on GLM and MiniMax. Existing fields are unchanged.
- No new knob, flag, log line, endpoint or default.

UI changes: optional. Per-token figures come from the difference between two `/v1/stats` reads divided by the `tokens_generated` difference (prefill reads in the window are included). Useful views: misses and reads a token, bytes a token, prefetch precision, the share of decode spent waiting (`decode_wait_seconds` delta over the decode seconds of the same requests), and the drive's busy rate. Benchmark results for this release: `benchmarks/results/prefetch-slow-drive-0.61.1/scorecard.jsonl` (arms GU5 / GU0: GLM prefetch on / off on the X10Pro; D1B0 / D1B0P0: DeepSeek at an emulated 1 GB/s under budget 0, prediction on / off) and `benchmarks/results/read-size-quant-0.61.1/roofline.json` (bf16, 2-bit and FP8 kernels against bytes a launch).

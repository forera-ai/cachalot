# Lab brief: runtime 0.61.0 (HANDOFF section 18.77)

Contract-file diffs first:

- New environment knob `CACHALOT_READ_THROTTLE_GBPS=B` (read by `cachalot.storage.reader` at import; unset, empty or 0 = off, the default; no `serve*.sh` or `chat*.sh` sets it). When set, every routed-expert read that the drive served (one slower than 1 ms; page-cache hits pass free) shares one process-wide pipe of B GB/s and is held until its bytes would have crossed it. It changes timing only, never outputs. It exists for storage-bandwidth sweeps (research charter L3 item 2); it applies to every model that reads experts through `ExpertReader`.
- No new `/v1/stats` field, log line, flag, endpoint or default. Existing fields show its effect: `expert_read_seconds` / `expert_reads` (mean read time grows with queueing), `expert_fast_reads`.

UI changes: none required. If Lab shows run manifests, the knob appears in a manifest's `CACHALOT_*` environment and should be displayed as "emulated drive bandwidth" so a throttled run is never mistaken for a real one. A curve view of the sweep is possible from `benchmarks/results/throttle-sweep-0.61.0/scorecard.jsonl` (ms a token against bandwidth; the arm name carries the bandwidth: INT, T4, T2, T1, USB, T1P0, USBP0).

# Lab brief: runtime 0.85.0, GLM prefill predicted read-ahead knob (HANDOFF section 18.276)

Contract-file diffs first. **One knob added, default off:** `CACHALOT_GLM_PREFILL_PREDICT_TOPK=k` (integer, default 0). Neither `serve-glm.sh` nor `chat-glm.sh` sets it, so no shipped launch changes. When k > 0, a GLM prefill chunk with fewer rows than `CACHALOT_GLM_SPECULATE_MIN_TOKENS` (512 in `serve-glm.sh`) reads ahead the union of its rows' top-k predicted experts for the next MoE layer instead of nothing. Outputs are bit-identical.

- **Measured:** inconclusive (`docs/glm-speed/G6B-RECORD.md`). In one session the knob was 3.8-9.2 % faster on 35-1,004-token prefills, but the arms without it were also 16 s slower on a cold system block the knob does not touch. Against an earlier clean baseline it was 2.6-4.5 % faster at 342-499 tokens and within 2.5 % below 240.
- **What Lab may show:** if Lab lists GLM environment knobs, add this one with its default (0, off) and the note "bit-identical, unresolved". A run with it on reports only different `prefill=` seconds in the `[request]` line.
- No `[request]` field, `/v1/stats` field, log line, endpoint, default or snapshot format changed; no numerics bump.

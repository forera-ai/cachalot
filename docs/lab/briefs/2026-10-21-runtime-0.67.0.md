# Lab brief: runtime 0.67.0, `CACHALOT_PREFILL_ENCODER_ONLY` (DI-1, default off; HANDOFF section 18.221)

Contract-file diffs first. **One new environment knob**: `CACHALOT_PREFILL_ENCODER_ONLY=1` (default `0`/unset, DeepSeek runtime only). Read when a text prompt of more than one prefill call is prepared (`generation.prepare_prompt`). No new CLI flag, endpoint, `/v1/stats` field, log line, startup phase or model family. `DeepSeek` `TextDecodeRuntime` gains `prefill_tokens(..., encoder_only=True)` and `finish_decoder()` (library API, not the server's HTTP API).

Behaviour with the knob on: each call of a multi-call prompt runs layers 0 to 19 and layer 20's compressed KV and index keys; the decoder half (layers 20 to 39) runs once, over the last 2,541 rows, at the requested snapshot boundaries and at the prompt's end. Snapshots are then taken only at those boundaries and at the end (the unpinned and in-block chunk-boundary snapshots are not). Outputs are not bit-identical to the knob-off path (rounding of the regrouped MoE, inside the noise a re-chunking already causes: `docs/DI1-BUILD-RESULTS.md`); knob off is bit-identical to 0.66.63. No numerics tag change: nothing re-prefills after upgrading.

UI notes for Lab: if Lab lists DeepSeek environment knobs, show this one as off by default with the note "output-changing, not yet quality-gated". The per-request `[request] prefill=` time is the place a difference would show; no new field.

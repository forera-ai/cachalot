# Lab brief: runtime 0.72.2, DI-1 stale-slot fix, failed requests logged (HANDOFF section 18.244)

## Contract changes

**One new log line.** When a streaming request fails, the server prints this on **stderr**:

```
[request failed] <ExceptionType>: <message>
```

- For any exception except a `ValueError`, Python's traceback follows the line.
- A `ValueError` is a bad request and gets the line only.
- No `[request]` line is printed for a failed request, as before.
- The client still receives `data: {"error": {"message": "<message>"}}` and then `[DONE]`. That is unchanged.

**One snapshot key changed.**
- DeepSeek disk snapshots made with DI-1 on are now keyed `0.68.0-di1.1` (was `0.68.0-di1`).
- The first request after updating prefills each saved system block once, cold: about 105 s for Hermes's 16k block.
- Full-prefill snapshots (`0.68.0`, `CACHALOT_PREFILL_ENCODER_ONLY=0`) are unchanged.

Nothing else changed: no knob, flag, default, `/v1/stats` field, `[request]` field, startup line or endpoint.

## What was fixed

DI-1's decoder tail could compute layer 20 with another expert's weights:
- On a 9,000-token prefill of 1017, 11 of 307 layer-20 experts were affected.
- When the memory governor had freed the slot instead, the same bug raised the `KeyError: 'w1.weight'` that Hermes showed as `openai.APIError: 'w1.weight'` in the first 1017 live session.

Every DI-1 quality number from 0.71.0 to 0.72.1 ran with this bug. DI-1's speed numbers stand.

## UI notes for Lab

- **Failed requests.** Show each `[request failed]` line as a failed request, with its type and message. Keep the traceback that follows it, up to the next non-indented line, as a collapsible detail.
- **Reading old logs.** Logs before 0.72.2 have no such line. A request missing its `[request]` line is the only sign of a failure there.
- **Expected cold prefill after updating.** Whatever snapshot-hit indicator Lab shows will show a miss and a cold prefill on the first request after the update. That is expected.

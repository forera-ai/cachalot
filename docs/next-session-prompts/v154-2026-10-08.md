## Rules that still hold, and two new ones

- **Lengthy tests need an estimate and Hamed's confirmation first, and minutes-remaining reports at checkpoints (Hamed, 2026-10-07).** New.

- **A decode lever of ~10 % is measured by per-turn or per-token alternation inside one process, parity swapped in a second** (§18.35): four
  separate processes in a row showed -1 % for a lever that alternation measured at -8.4 %, because process-to-process drift is +-10 %. The
  instruments (scratch, rebuild from §18.35): `glm_stream_alt.py` (agent-shaped turns through `GlmModel.stream()`, a module knob flipped per turn)
  and `TF_ALTERNATE` for per-token flips (a shim module for an instance attribute, `tfmir.py`). New.
- **A benchmark of a cache effect needs cold pages:** a file just copied or written is in the page cache and `F_NOCACHE` does not evict it;
  `purge` needs sudo and a 60 GiB anonymous memory hog did not evict either (§18.34). Write the file with `F_NOCACHE` or use untouched layers. New.
- **Anything new on `GlmModel` / `GlmEngine` must tolerate `MiniMaxModel`** (it subclasses `GlmModel` without running its `__init__`, so attributes
  set there do not exist; use `getattr`); the loop-guard tests caught the 0.51.0 slip (§18.39). New.
- **Running the Hermes CLI updates Hermes itself** (dependencies, desktop app rebuild, skills, config format; §18.38): not avoidable with an isolated
  `HERMES_HOME`; tell Hamed. Hermes answers images through its `vision_analyze` tool (120 s default timeout). New.
- **zsh does not word-split unquoted variables**: `for c in "1 0:3"; do f $c` passes one argument; use `${=c}` or explicit arguments. New.

- **A governor or memory change is measured by the server-path replay under held memory** (§18.24): other
  processes holding GPU and host memory (`hold.py`, `hoghost.py`), a pressure/swap/"Alloc" sampler every 2 s, and
  both a cold start (empty snapshot directory plus the saved warm set) and a warm one; one pair can show a stall the
  next does not. And a background waiter's own command line must not contain `deepseek-v41/bin/python`: the serve
  guard matched it and four arms never started (§18.24). New.

- **A server-path memory A/B logs the GPU driver's "Alloc" and MLX's buffer cache during decode, not only after it**
  (§18.22): the governor's own reads clear the cache first and never see the overshoot. New.

- **A decode lever that wins under `TF_ALTERNATE` must also win through `stream_agent.py`** (§18.19 item 8): the
  in-process 1.9 ms did not survive the server path's noise. New.

- **A budget A/B goes through `stream()`**, not `minimax_followup_turns.py` (§18.18 item 2), and logs available
  memory, swap and the driver's "Alloc" beside it: a budget that swaps at load looks fine for a turn or two. New.

- **Nothing else on the GPU during an arm, and read the driver's counters when an arm looks slow**: another
  process's 2 GiB of GPU memory doubled short prefills (§18.17 item 3). Hamed working on the machine (Finder, a
  terminal `top`) made one arm decode at 420 ms. New.

- **Never put Hamed's Mac or its display to sleep** (his instruction, §18.20): no `pmset displaysleepnow`. The
  screensaver still renders on the GPU (~13 %, §18.16 item 7): check `pgrep -f Flurry.appex` is empty before an arm,
  compare arms only within one display state, or ask Hamed to set the screensaver to Never. New.

- **A long MiniMax prefill in `glm_prefill_timeline.py` needs `FIT_PREFILL=1`** and
  `CACHALOT_MINIMAX_PREFILL_FULL_TOKENS=512` (§18.20 item 1): otherwise 16k OOMs at 68 GiB. New.
- **A tool that deletes files it read must close them first**: an open descriptor keeps an unlinked file's blocks
  allocated, and the bank rewrite filled the disk that way (§18.16 item 1). New.

- **Memory decisions read `kern.memorystatus_level`, not free pages** (§18.15 item 7): free pages sit near 0.5 GiB at
  normal pressure; `vm_stat`'s free column alone would have parked slabs for nothing. New.
- **Do not edit `src/` while a benchmark sweep runs**: every arm is a new process that imports the tree as it is
  then (§18.15: a sweep was restarted for this). New.

- **Read what the host needs from the sync itself.** Any MLX op on an evaluated array (a cast, a sort, a reshape
  before `.tolist()`) is another GPU round trip, ~0.4 ms a MiniMax layer, ~21 ms a token (§18.9, §18.1). Put the
  cast inside the graph that `mx.eval` covers, then `np.array` it.
- **MiniMax follow-up benchmarks with a pause need `HEARTBEAT=0.5`**, or the idle Metal queue adds ~1 s to every
  prefill (§18.9).

- **A server A/B at long context needs the display state fixed**: `caffeinate -u -t N` holds the display on for an
  arm (§18.6); the slowness it exposes did not show with the display off. And launch servers from a script, not a
  command line containing `deepseek-v41/bin/python` or `cachalot.cli`: the serve scripts' guard matches it, and a
  `pkill -f "cachalot.cli serve"` in the same command line kills the caller. New.

- **`TF_ALTERNATE` needs swapped pairs** (§18.14): arm A gets the even tokens, arm B the odd ones, and those token
  sets differ by up to ~12 ms a token on the same code. Run `A:B` and `B:A` on the same text and average each
  arm over both. New.

- **Decide MiniMax decode switches in one process.** In §18.5 the read time per miss drifted 3.5 → 4.0 ms (once
  5.0) across back-to-back processes and the non-read part 82 → 134 ms on the same code; every shipped change was
  decided by `TF_ALTERNATE` (knobs: `cachalot.storage.reader:BYPASS_OVERRIDE`,
  `cachalot.minimax.coded_bank:MIRROR_FRACTION`, `cachalot.glm.experts:DECODE_HIT_OVERLAP`). New.

- **A decode switch on MiniMax at long context: `TF_ALTERNATE=module:NAME:A:B`** (§18.3), one process, token by
  token. Three back-to-back 32k processes gave "other" 125 / 135 / 109 ms on the same code. New.
- **Decode A/Bs on MiniMax: same text for both arms, not fresh text.** Decode speed is dominated by the text's
  routing (one configuration ran 239-394 ms per token across four texts); the page cache carries nothing between processes
  under this load (`fast_reads` 0), so the same-text pair is the fair one. Prefill A/Bs still want fresh text on
  DeepSeek. And nothing else on the machine during an arm: a CPU-only replay beside one slowed its prefill 13 %. New.
- **Any new model path caps MLX's buffer cache** (`mx.set_cache_limit`). GLM ran without one until 0.18.0 and swapped
  as soon as the wired set grew (§17.1).
- **Replay a dump before touching a cache**, restarts included (`benchmarks/snapshot_store_replay.py`).
- **A prefill A/B needs fresh text per arm** (`FILLER_FILE`/`FILLER_OFFSET`); a 3.5 MB concatenation of the repo's
  `.md` and `.py` files gives room for dozens of arms (§17.1). And now: **alternate arms and look for drift**
  before reading means (§15.13).
- **`snapshot_store.NUMERICS_VERSION` / `glm.snapshots.GLM_NUMERICS_VERSION` move with numerics, not releases.**
- **A slow-window A/B needs a slow window**; separate processes, interleaved; never two runtimes at once.
- **MLX 0.32 arrays belong to the thread that built them until evaluated** (§15.6).
- **Hermes changes under you.** Diff the dumped system prompt (and `reasoning_effort`) before assuming a cache bug.
- `serve.sh` / `serve-glm.sh` guard with `pgrep -f "deepseek-v41/bin/python|cachalot\.cli"`: launch them from a
  command line that contains neither (a `pkill -f "cachalot.cli serve"` in the same shell command trips it).
- One change at a time, measured. Terse in chat, complete prose in files. Full copy-paste commands.
